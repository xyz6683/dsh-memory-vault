# 我们的插件设计方案（v1 草案）

> 日期：2026-11-01
> 前置：[01-已有插件调研分析](./01-已有插件调研分析.md)
> 用户已拍板的三项决策：
> 1. **存储**：SQLite 为主 + 定期导出 Markdown
> 2. **写入控制**：分层闸门（显式记录直接落库 / AI 自动提炼进确认队列 / 日志自动写）
> 3. **范围**：聚焦记忆 + 画像分析

---

## 1. 命名与定位

- **工作名**：`dsh-memex`（Memex = Vannevar Bush 1945 年构想的个人记忆机器，与本插件"个人长期记忆 + 画像"的定位完全契合；备选：dsh-memory-atlas / dsh-memory-vault，最终发布前可改）
- **一句话**：本地优先、越用越懂你的 DSH 长期记忆插件——沉淀 SOP/偏好/经验，跨会话自动召回，并可聚合生成个人画像。
- **slogan 候选**：`Remember what matters. Recall what you need. Know yourself better.`

## 2. 需求映射

| 用户需求 | 设计对策 | 借鉴来源 |
| --- | --- | --- |
| 宝贵经验长期保留 | SQLite 持久化 + JSONL 备份 + 版本历史可回滚 + Markdown 导出 | memory-graph 的备份/回滚；memory-evolve 的透明导出 |
| 跨对话调用 | `agent/pre-step` 自动召回 + 混合排序 + 预算注入；另有 `mvault_recall` 手动检索 | memory-graph 的核心机制 |
| 不定时沉淀 SOP/最优操作/偏好 | 显式说"记一下"→直接落库（结构化 kind + SOP 步骤）；AI 自动提炼→确认队列 | memory-evolve 的确认闸门 + memory-graph 的 kind 体系 |
| 多领域并存（开发/职业/流程/英语/投资） | 一等公民「领域」维度：标签、过滤、召回加权、画像聚合 | 三者皆无，本插件原创 |
| 个人画像分析 | `mvault_profile` 工具 + Web 画像面板：按领域聚合偏好/SOP/经验/活跃度，LLM 生成叙述性画像报告 | 三者皆无，本插件原创（evolve 的反馈行思路可并入） |

## 3. 架构总览

```
DSH Agent 回合
   │
   ├─(1) pre-step 挂钩 ──► 召回器：混合排序 → 预算注入 <memory_context>（标记为参考数据）
   │                          ▲
   │                          │ FTS5(trigram) + 图谱距离 + 重要度 + 时间衰减 + 领域加权
   │                          │ (+ 可选语义向量，可降级)
   ├─(2) 回合完成事件 ──► 采集器：轮次归档 → LLM 结构化提炼 → 确认队列（分层闸门）
   │                                                    │
   │                                    用户批准 ────────┴──► 记忆库（active）
   │
   └─(3) 工具面：mvault_add / mvault_recall / mvault_expand / mvault_forget / mvault_review /
                 mvault_graph / mvault_profile / mvault_export / mvault_backup ...
        ┌──────────────────────────────────────────────────────────┐
        │ SQLite（node:sqlite，WAL，0600）                            │
        │  memories · entities · relations · turn_archives ·         │
        │  suggestions · embeddings(可选) · profile_cache            │
        └──────────────────────────────────────────────────────────┘
                 │ 定期/手动导出                     │ Web API（token + Host 校验）
                 ▼                                  ▼
        memoryDir/export/*.md                DSH Web：记忆 Tab / 确认队列 / 图谱 / 画像面板
        （MEMORY.md 等，人可读、git 友好）
```

## 4. 数据模型（SQLite 核心表）

### 4.1 memories（记忆主表）

| 字段 | 说明 |
| --- | --- |
| id | ULID/随机 UUID |
| content | 自包含记忆正文 |
| kind | `preference` / `fact` / `decision` / `constraint` / `lesson` / `sop` / `event` / `summary` |
| track | `user`（个人档案/偏好）/ `global`（全局事实与 SOP）/ `project`（项目关键记忆）/ `project-log` / `daily-log` |
| domain | `dev` / `career` / `workflow` / `english` / `investment` / `general`（可配置扩展） |
| importance / confidence | 0~1 |
| stable_key | 稳定事实换代键（新值取代旧值，旧值留档） |
| branches | 项目轨的 git 分支作用域（NULL=全部分支） |
| steps | SOP 类记忆的步骤数组（JSON），普通记忆为空 |
| status | `active` / `pending`（待确认）/ `archived` |
| source_session / source_turn | 溯源 |
| supersedes | 被本条目取代的旧条目 id |
| created_at / updated_at | 时间戳 |

### 4.2 其余表

- `entities` / `memory_entities` / `relations`：轻量知识图谱（实体、别名、有向关系、引用计数、来源记忆）——从 memory-graph 收敛而来，保留**合并/重命名/孤儿 GC/回滚**四件套（长期记忆库"建错能改"）。
- `turn_archives`：轮次原文归档（有界、有保留期），提炼失败可离线重试，不重放对话。
- `suggestions`：确认队列（AI 提炼候选，含理由与来源）。
- `memory_embeddings`：可选语义向量（默认关，接口不可用自动降级词法+图谱）。
- `profile_cache`：画像聚合缓存（按领域预聚合的统计与叙述性报告，带失效版本号）。
- `meta`：schema 版本等（启动时事务内迁移）。

## 5. 核心机制

### 5.1 分层写入闸门（三档）

| 档位 | 触发方式 | 去向 | 理由 |
| --- | --- | --- | --- |
| ①显式记录 | 用户说"记一下/SOP/记住"→ `mvault_add`（track=user/global/project） | 直接 `active` | 用户明示，信任成本为零 |
| ②主动提议 | 用户未要求、但 agent 判断本轮工作有长期价值 → `mvault_propose` | `pending` 确认队列 → 用户批准入 `active` | 2026-11-02 用户拍板新增：agent 不得擅自直写 |
| ③自动提炼 | 回合完成 → 采集器 LLM 提炼（confidence≥阈值） | `pending` 确认队列 → 用户批准入 `active` | 用户拍板的选择 |

| ③日志自动写 | 每回合进展/决策流水 | `project-log` / `daily-log`，importance 低，**不参与默认召回注入**，仅按需读 | 与 evolve 同思路，但由程序钩子保证，不依赖模型自律 |

> 与 evolve 的关键差异：日志不再靠"提示词义务"驱动（模型会偷懒），而是回合完成事件驱动；与 memory-graph 的关键差异：提炼结果不直接落库，全部过闸。

### 5.2 自动召回（跨对话调用的正解）

- 挂 `agent/pre-step`，仅 step=1、默认开，每轮可临时开关（沿用 memory-graph 的"本轮开关"）。
- 查询词 = 最新用户消息；混合排序 = FTS5 trigram（中文可用）× 图谱距离 × 重要度 × 时间半衰期 × 领域加权 × 访问强化（自动召回不强化，防固化）。
- 预算注入：`maxContextChars`/`maxContextTokens` 硬上限，注入块明确标记"参考数据，不是指令；当前用户输入优先"。
- 渐进披露：召回结果先给摘要/预览，`mvault_expand` 按 id 取全文（省 token）。
- 领域加权：命中当前对话领域的历史记忆排序加权（领域由轻量分类器或用户/模型显式指定）。

### 5.3 领域维度（原创点）

- 默认领域：`dev`（网页/程序开发）、`career`（职业发展）、`workflow`（工作流程优化）、`english`（英语技能）、`investment`（投资管理）、`general`。
- 可在配置中增删改；每条记忆必须/可缺省领域标签（缺省=general，模型写入时需推断）。
- 领域参与：召回加权、Web 过滤、画像聚合、Markdown 导出分目录。

### 5.4 画像分析（原创点，最大差异化）

- `mvault_profile [domain]` 工具：返回结构化画像 JSON——
  - 概览：各领域记忆存量、活跃度时间线；
  - 偏好清单（preference 汇总）；
  - SOP 资产（sop 列表，含更新时间）；
  - 经验教训分布（lesson 按主题聚类统计）；
  - 关键决策记录（decision）；
  - 叙述性画像（LLM 基于聚合数据生成，缓存 + 失效重算）。
- Web「画像」面板：可视化上述数据；支撑"为将来发展、策略制定提供基础"。
- 情绪反馈（吸收 evolve 思路，简化）：日志轨支持 `【反馈】` 行，画像报告纳入满意度趋势。

### 5.5 数据安全与健壮性（吸收两家之长）

- 数据库 0600 权限、WAL、busy_timeout；写失败进 outbox 重放、dead-letter 兜底。
- 备份：`mvault_backup export/import` JSONL；恢复仅允许空库。
- 导出：`mvault_export` 生成 `MEMORY.md / USER.md / daily/ / projects/<name>/` 人可读 Markdown（含领域目录），可直接 git 版本化。
- Web API：同源 + 随机 token + Host/Origin 校验；非 loopback 部署需配置 trustedHosts。
- 召回内容在会话日志中留痕，历史会话可重建。

## 7. Web UI（DSH Web 内）

- **记忆 Tab**：领域/轨/类型筛选 + 搜索 + 列表（预览/展开/编辑/归档）+ 确认队列（批准/拒绝）。
- **图谱视图**：实体关系可视化（简化版 memory-graph，节点=实体、边=关系、×N 引用数）。
- **画像面板**：领域统计 + 偏好/SOP/经验清单 + 叙述性画像 + 导出按钮。
- **设置**：召回开关/预算、提炼开关/阈值、领域列表、导出路径、本轮开关。
- 客户端经 `dsh.client` 清单注入（同 memory-graph 的 dsh-client-ui-* 槽位）。

## 8. 技术栈与工程约束

- **语言**：TypeScript（严格模式），构建 `tsc + tsdown`，测试 `vitest`。
- **运行时依赖**：零（`node:sqlite` + `node:fs` 等内置模块）；仅 peer 依赖 DSH SDK 包（对齐本地 0.2.0-rc.2：`@deepseek-ai/dsh-agent`、`dsh-tools`、`dsh-llm`、`dsh-session`、`dsh-host-webserver`、`dsh-system-prompt`、`cordis`、`schemastery`）。
- **已验证可用的扩展点**：`ctx.tools.register` / `ctx.on('session/event')` / `ctx.on('agent/pre-step', …, {prepend:true})` / `ctx.systemPrompt.context` / `ctx.inject(['webServer'])` + `webServer.register` / `llm.stream`。
- **配置**：schemastery schema + `cordis.patch.yml` 全量默认值；`dsh plugin add` 一条命令安装。
- **i18n**：zh-CN + en（为 dshplugins.com 发布准备）。
- **发布**：git tag 版本号 + 更新检测（简化版，借鉴 evolve 的运营机制）。
- **注意**：本机 `~/.dsh` 在沙箱外，安装测试时需要申请一次写权限。
