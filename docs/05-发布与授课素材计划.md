# 发布与授课素材计划

> M4 目标：把 dsh-memory-vault 发布到插件目录，并把全过程整理成 agent 选修课授课素材。
> 调研结论（2026-11-02，实测两个渠道）：

## 发布渠道

### 1. dshplugin.store（自动收录，零提交成本）

- 机制：**自动同步 GitHub topic `dsh-plugin`**（目前已收录 22,975 个仓库）。
- 动作：仓库公开 + 打上 `dsh-plugin` topic，等待同步即可（按类别/名称/描述可搜）。
- 无人工审核；质量取决于 README 与 topic 元数据。

### 2. dshplugins.com（人工审核的精品目录）

- 提交入口：https://dshplugins.com/submit（需要登录会话）。
- 审核要求（页面原文提炼）：
  1. README 必须写明**精确的 profile 安装步骤**；
  2. 说明**前置条件、权限、凭据、支持平台、已知限制**；
  3. 使用**规范 GitHub 仓库 URL**；fork/重复仓库可能被拒；
  4. 不得分发恶意、欺骗或侵权内容。
- 收录后展示：安装命令、README 快照、推荐按钮、作者可见。

### 授课要点（预埋的"金句"）

1. **先调研再动手**：三家的长板拼图 = 我们的起点（召回正解 + 闸门工作流 + 画像原创点）。
2. **产品决策在代码前锁定**：存储/闸门/范围三问，用户拍板后才写代码。
3. **纯插件路线的边界**：只用公开扩展点（tools / agent-pre-step / systemPrompt / webServer / slots），零核心修改，卸载即净。
4. **失败开放的工程纪律**：LLM 提炼失败只告警不阻塞；embedding/网络降级词法召回；outbox 兜底写失败。
5. **AI 写入必须过闸门**：确认队列是信任设计，不是功能清单项。
6. **领域画像**：确定性聚合 + 可选 LLM 叙述，数据可信、结论可查。
7. **发布双通道**：topic 自动收录保底 + 人工目录做精品背书。
